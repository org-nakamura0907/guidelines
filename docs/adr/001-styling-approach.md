# ADR-001: スタイリング手法の選定

- **Status**: Accepted
- **Date**: 2026-07-17

---

## 背景

Astro で構築したガイドラインサイトにスタイリングを導入するにあたり、手法を選定する必要がある。
現時点ではコンポーネントは存在せず、ページは MDX コンテンツを直接描画するのみの状態である。

候補として以下を検討した。

| 選択肢       | 概要                                                                                   |
| ------------ | -------------------------------------------------------------------------------------- |
| Starlight    | Astro 公式のドキュメントサイト向けフレームワーク。ナビゲーション・目次・検索などが同梱 |
| Tailwind CSS | ユーティリティファーストの CSS フレームワーク。Astro 公式インテグレーションあり        |
| Plain CSS    | グローバル CSS と Astro scoped styles のみ。外部依存なし                               |

## 決定

**Tailwind CSS** を採用する。

## 理由

- 独自デザインを作り込む方針のため、Starlight の提供するデフォルト UI は制約になる
- Tailwind CSS は `@astrojs/tailwind` による公式インテグレーションがあり、Astro との親和性が高い
- ユーティリティクラスベースの設計により、コンポーネントが増えた際にも一貫したスタイル管理が可能
- Plain CSS と比較して、レスポンシブ対応・ダークモード等の実装コストが低い

## 影響

- **メリット**: 柔軟なデザインが可能。コンポーネント追加時の拡張性が高い
- **デメリット**: UI コンポーネントを自前で実装する必要がある（Starlight のような既製 UI は得られない）
- **中立**: `@astrojs/tailwind` および Tailwind CSS v4 のセットアップが必要
