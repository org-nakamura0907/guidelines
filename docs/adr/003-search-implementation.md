# ADR-003: ページ内検索の実装方針

- **Status**: Accepted
- **Date**: 2026-07-19

---

## 背景

ドキュメントサイトとして、コンテンツが増えるにつれてキーワードで目的のページを探せる検索機能が必要になる。追加インフラを持たない静的サイトでの実現方法を検討した。

候補として以下を検討した。

| 選択肢            | 概要                                                                                |
| ----------------- | ----------------------------------------------------------------------------------- |
| Pagefind          | 静的サイト向けの全文検索ライブラリ。ビルド後の HTML からインデックスを生成          |
| Algolia DocSearch | SaaS 型の検索サービス。高機能だが外部依存が発生する                                 |
| Fuse.js           | クライアントサイドの fuzzy 検索ライブラリ。インデックスをバンドルに含める必要がある |

## 決定

**Pagefind** を採用する。

UI は Pagefind の Default UI (`pagefind-ui.js`) を利用し、ヘッダーの検索ボタンから開くモーダル内に表示する。

## 理由

- 静的サイトのビルド成果物 (`dist/`) を走査してインデックスを生成するため、外部サービスへの依存がない
- JS ファイルを遅延ロードする設計のため、初期表示パフォーマンスへの影響が最小限
- Fuse.js と異なり、全コンテンツのインデックスをバンドルに含めないため、コンテンツが増えても初期ロードサイズが増大しない
- Algolia と異なり、API キーや利用制限を考慮する必要がない

## 実装上の決定事項

**`bundlePath` の明示指定**
Astro の `base` オプション (`/guidelines`) があるため、Pagefind が内部で読み込む `pagefind.js` のパスがルートからの相対パスで解決されてしまう。`bundlePath: withBasePath("/pagefind/")` を明示することで正しいパスに誘導する。

**Vite の `external` 設定**
`/pagefind/pagefind-ui.js` はビルド後に生成されるファイルのため、Vite のバンドル対象から除外する (`rollupOptions.external`)。

**`index` frontmatter フィールド**
トップページのようなインデックス対象外にしたいページを、`data-pagefind-ignore` ではなく `data-pagefind-body` の付与を省略することで除外する。`data-pagefind-body` と `data-pagefind-ignore` が同一要素に共存した場合、前者が優先されるため。

## 影響

- **メリット**: 追加インフラ・API キー不要で全文検索を実現できる
- **デメリット**: `astro dev` では動作せず、`npm run build && npm run preview` でしか検索機能を確認できない
- **中立**: 日本語のステミング (語幹処理) は非対応。完全一致・前方一致のみで動作する
