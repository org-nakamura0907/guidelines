# ADR-004: CI ワークフローの設計方針

- **Status**: Accepted
- **Date**: 2026-07-19

---

## 背景

GitHub Actions を用いた CI を整備するにあたり、どのジョブをどのタイミングで実行するかを設計する必要がある。

特に E2E テストは `npm run build` が必要なため実行時間が長く、PR のたびに実行すると開発体験が低下する可能性がある。

## 決定

ワークフローを **2ファイルに分離** する。

| ファイル  | トリガー                    | 内容                                            |
| --------- | --------------------------- | ----------------------------------------------- |
| `ci.yml`  | PR (non-draft) / main push  | Lint, Build, Unit テスト, 依存関係 Audit        |
| `e2e.yml` | 週次 (月曜 0:00 UTC) / 手動 | E2E テスト (Playwright), アクセシビリティテスト |

## 理由

**E2E を分離した理由**

- E2E は `npm run build` を含むため実行時間が長い (2分以上)
- ドキュメントサイトの E2E は機能の破壊的変更を検知するためのもので、PR ごとの実行は過剰
- 週次実行により、依存関係の更新 (Dependabot) や環境変化による回帰を定期的に検知できる

**draft PR を除外した理由**

- 作業中の PR に対してCI リソースを消費しないため

**ジョブを並列化した理由**

- Lint / Build / Test / Audit は互いに依存しないため並列実行によりフィードバックを高速化できる

**アクション SHA ピン留めの理由**

- `actions/checkout@v4` のようなタグ参照はタグの書き換えによるサプライチェーン攻撃のリスクがある
- コミット SHA で固定することで意図しないアクションの変更を防ぐ

## 影響

- **メリット**: PR ごとの CI が高速に完了する。E2E の失敗が週次で検知される
- **デメリット**: E2E の問題が PR マージ時点では発覚しない可能性がある
- **中立**: Dependabot によるアクションのバージョンアップは SHA の更新として PR が作成される
